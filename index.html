Headgate

PR triage for agent fleets. Your coding agents now open more pull requests in a week than your team can read in a month — Headgate groups the flood, scores each PR from plain checkable facts, and hands you one digest a day, riskiest first.

Repository on GitHub · Apache-2.0 · TypeScript / Node 24+ · Fastify + React + Postgres

What makes it different

  • The digest is the product. One ordered list a day, stored as a versioned digest/1 artifact with a SHA-256 id. A human works it in an hour.
  • Deterministic, explainable risk scores. Every point lists its reason — size, blast radius, tests, author fleet, overlap, churn, staleness, duplication, static patterns. No LLM anywhere in scoring, reviewing, or summarizing.
  • Clustering with reasons. Related PRs become one cluster — same files, same ticket, same branch lineage, near-identical diff — and the digest shows why they were grouped, so a human can split them.
  • Human decisions are recorded. Reviewed, snooze, assign, escalate, split, merge — every queue action goes into a hash-chained audit log, anchored so tail truncation fails verification.
  • It never writes to GitHub. No approvals, no merges, no comments, no labels. Read-only app permissions by design.

Honest limits — stated, not hidden

  • This demo used seeded test data. No real GitHub, no real PRs — the fleet here is ten hand-written PRs fed through the dev endpoint. The pipeline they went through is the real one.
  • A risk score is a heuristic, not a verdict. A 10-line diff can delete a database; a 5,000-line diff can be generated tests. The score orders attention; it never certifies safety.
  • Clustering can mis-group. Two PRs touching the same files may be unrelated; two PRs on the same ticket may touch disjoint files. The digest shows its edge reasons so a human can see why — and split them.
  • Scores are computed at ingestion. The first copy of a duplicated change scores lower than the later copies, which see the overlap. The digest orders by the stored scores.
  • The digest is stale by construction. A PR opened after the daily digest waits until tomorrow — or until someone opens the live queue in the web UI.
  • GitHub-only in v1. The ingestion layer is behind an interface, so a second forge is a new adapter, not a rewrite.
  • Audit log is tamper-evident, not tamper-proof. A coordinated rewrite of the chain and its head anchor is still undetectable without an off-box checkpoint.

Run it yourself

git clone https://github.com/TamTunnel/headgate.git
cd headgate
npm ci
# Needs Postgres 16+; see README for the database setup.
# Local development without GitHub:
GITHUB_CLIENT=fake npm start
# Seed a PR, then deliver a signed webhook (see scripts/smoke.mjs),
# or just run the smoke script:
npm run smoke
